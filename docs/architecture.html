The backend is a single Cloudflare Worker at juyo.razvanfrandes.com. Three Durable Objects run their agent loop on Pi Durable. Every number comes from SQL in a Postgres database that the Worker reaches through Hyperdrive and a Cloudflare Tunnel, with a role that can only read.

    Principles enforced by the architecture

    • The model never computes a number

      Metric definitions live in SQL views and functions. The agents call tools that run that SQL; the model plans the calls and explains the result.

    • Evidence travels with every result

      Each tool result carries its SQL, parameters, period, sources and metric definitions. The chat sends them to the app as evidence.

    • One door to the data

      Kassandra, the workflow builder, workflow runs and outside MCP clients all use the same catalog of 24 tools, with the same guard.

    • Durable by construction

      The three agents run on Pi Durable. A conversation, a draft or a run survives a deploy or an eviction, and a run that waits for approval holds no compute.

    • Compass only reads

      The database role can only SELECT. An approved action becomes an RMS task for the revenue manager and an audit entry. Nothing is written to a source system.

    • A person decides on prices and channels

      adjust_bar, close_channel and open_channel are high risk in code, whatever the model says. No autonomy level applies them alone.

    • One spec for people and AI

      The builder agent and a person editing by hand change the same WorkflowSpec draft. The graph is derived from it, so every graph can run.

    • The answer comes to you

      A cron runs fixed SQL detectors at 05:00 UTC, before anyone opens the app. The model only writes the sentence that summarises each finding.

    Security of a public demo

    There is no login: reviewers use the app and the MCP endpoint as they are, and every model call is paid from the owner's key. The limits below keep the public surface safe and the daily spend bounded.

    • DatabaseRead-only role

      compass_ro has SELECT on schema hotel only, and every transaction is read-only. Postgres listens on localhost; the VM has no inbound port.

    • Custom SQLSQL guard and statement timeout

      run_readonly_query accepts one SELECT, refuses pg_* names, locks and session statements, and is wrapped to 200 rows of at most 32 KB. The role stops any statement at 5 s.

    • Prompt injection<untrusted_data> wrapping

      Guest reviews, account names and custom query results reach the model inside the tag, with < escaped. The system prompt treats that text as data, never as instructions.

    • SpendDaily budgets and rate limits

      Per UTC day, for all visitors: 300 questions, 60 workflow runs, 120 decisions, 24 brief refreshes, 2000 embeddings. Per client: 6 questions and 60 MCP requests per minute. At most 30 enabled workflows.

    • EmailLimits on mail from our domain

      3 per hour and 6 per day per address, 10 per hour per client, 50 per day for everyone. One recipient per workflow, a fixed template, and every outside link removed.

    • PrivacyMasked addresses

      API answers, the audit log, graph labels and run logs show si****@gmail.com. Only the builder socket shows the address, and its draft id is a random secret. Quota counters key on a hash.

    • MCPNo CORS on /mcp

      Responses carry no Access-Control-* headers and browser requests from other origins get 403, so a web page cannot read an MCP answer. Bodies are at most 64 KB.

    • APISame-origin writes, no internals in errors

      Mutating /api calls from another site get 403, and both sockets check their Origin. JSON bodies are at most 16 KB. Unexpected errors return a generic 500 and go to the logs.

    • AcceptedWhat the demo does not prevent

      Without a login, a visitor can use up the day's budget or approve a proposal. Nothing outside Compass changes, and the cost of a bad day is capped.
